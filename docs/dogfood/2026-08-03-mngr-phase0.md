# mngr Phase 0 — feasibility findings

**Date:** 2026-08-03
**Plan:** `docs/superpowers/plans/2026-08-03-mngr-agent-backend.md` (Task 0)
**Spec:** `docs/superpowers/specs/2026-08-03-mngr-agent-backend-design.md`
**Host:** macOS (arm64, Darwin 25.5), local provider only

**Verdict: PROCEED, with one mandatory design change to Task 4.**
Q1 PASS (with a documented caveat), Q2 FAIL-as-designed → PASS only via an
explicit remedy that is now a hard requirement, Q3 answered.

## Install

`uv tool install git+https://github.com/imbue-ai/mngr` **fails** — the repo is a
flat-layout monorepo (`libs/`, `apps/`) that setuptools refuses to build. The
published PyPI package is what works:

```bash
uv tool install imbue-mngr                          # mngr 0.2.17
uv tool install imbue-mngr --with imbue-mngr-claude # adds the claude agent type
```

The README's quick install (`curl … install.sh | bash`) was deliberately not
used; the documented manual path gives the same result without piping a remote
script into a shell.

The `claude` agent type is a **separate plugin** and is not present in a bare
install. Without it, `mngr plugin list` shows only `command`, `docker`,
`headless_command`, `local`, `ssh`. `mngr extras -i` / `mngr plugin
install-wizard` are interactive TUIs and cannot be driven headlessly; installing
`imbue-mngr-claude` into the tool environment achieves the same thing and is
scriptable.

Prerequisites present before starting: Python 3.12.13, uv 0.11.16, jq 1.7.1,
git 2.50.1, node 24.14.1, claude CLI 2.1.196. Installed during Phase 0:
tmux 3.7b, bash 5.3.15.

### Undeclared dependency: bash 4+

**mngr 0.2.17 does not run on stock macOS.** Its
`$MNGR_AGENT_STATE_DIR/commands/stream_transcript.sh` uses `declare -A`
(associative arrays, bash 4+) at lines 46, 47, and 52. macOS ships bash 3.2.57.
The failure is not graceful: the script crash-loops in the agent's tmux pane,
Claude never starts, and `mngr message` fails with a 90-second timeout.

```
stream_transcript.sh: line 46: declare: -A: invalid option
```

mngr's documented core dependencies are `git`, `tmux`, `jq` — bash 4+ is not
listed. The shebang is `#!/usr/bin/env bash`, so `brew install bash` (5.3.15 at
`/opt/homebrew/bin/bash`, ahead of `/bin` on PATH) resolves it without touching
Apple's `/bin/bash` or the login shell. **An existing agent does not pick up the
new bash** — it must be destroyed and recreated, and the tmux server killed.

Worth reporting upstream.

## Q1 — does `mngr create` spawn a working Claude Code agent? PASS (caveated)

After installing bash 5, the full pipeline works:

```bash
mngr create probe2 claude --no-connect -y
mngr message probe2 -m "Reply with exactly one word: pong"
mngr transcript probe2 --format jsonl
```

The agent spawns, reaches a live Claude Code prompt, receives the message, and
produces transcript events:

```json
{"type":"user_message","role":"user","content":"Reply with exactly one word: pong", …}
{"type":"assistant_message","role":"assistant","text":"Not logged in · Please run /login", …}
```

**Caveat:** no *model* response was obtained, because the spawned agent had no
credential. The operator's claude.ai login lives in the macOS keychain, which
the tmux-spawned process cannot reach, and no `CLAUDE_CODE_OAUTH_TOKEN` was set
in the environment. This is not a defect — it is the Q2 story from the other
side, and it confirms that credentials must be injected deliberately. The
mechanism under test (spawn → message → transcript) is proven end-to-end.

Flags that matter: `--no-connect` (otherwise `create` attaches an interactive
tmux session) and `-y`.

### Two rough edges

- `mngr create` refuses to run when a file is ignored only by the user's global
  gitignore (it warns that remote provisioning would fail). Adding the path to
  the repository's own `.gitignore` clears it.
- `mngr destroy` leaves the created git branch behind unless `-b` is passed, so
  recreating an agent under the same name fails with
  `fatal: a branch named 'mngr/<name>' already exists`.

### `mngr message` reports failure on a message it delivered

`mngr message` exited non-zero with
`Timeout waiting for message submission signal (waited 90.0s)` — but the
transcript shows the message *was* delivered and answered. **Task 4's `send()`
must not treat a non-zero exit as proof of non-delivery.** Reconcile against the
transcript before surfacing an error event, or a working turn will be reported
to the operator as a failure.

## Q2 — can Rhumb dictate the credential environment? FAIL by default, PASS with remedy

**This is the finding that changes the implementation.**

### mngr does not scrub the ambient environment

With decoys exported *before* the tmux server started, then a `command` agent
spawned to dump its own `env`:

| Variable | Reached the agent? |
| --- | --- |
| `ANTHROPIC_API_KEY=sk-decoy-must-not-survive` | **YES** |
| `ANTHROPIC_BASE_URL=https://decoy-redirect.invalid` | **YES** |
| `RHUMB_AMBIENT_DECOY=ambient-leaked` | **YES** |

An ambient `ANTHROPIC_BASE_URL` reaching the agent is exactly the silent
model-traffic redirection `provider.ts` exists to prevent.

### The tmux daemon inheritance hazard is real — and it produced a false negative

The first run of this test appeared to pass. It did not. The agent's environment
comes from **whatever the tmux server was started with**, not from the
environment of the `mngr` process that requested the agent. In the first run the
tmux server predated the decoy exports, so the decoys were absent — while
unrelated `CLAUDE_CODE_*` vars from the *earlier* shell were present. The test
only becomes meaningful after `tmux kill-server`.

Any future test of this property must kill the tmux server first, or it silently
measures nothing. This is precisely the hazard the spec predicted.

### The remedy: `--env` overrides inherited values

`mngr create` accepts `--env KEY=VALUE` (also `--env-file`, `--pass-env`), and
**`--env` wins over the inherited tmux-server environment**, including blanking a
variable with an empty assignment:

```bash
mngr create envprobe3 command \
  --env ANTHROPIC_API_KEY=scrubbed-by-rhumb \
  --env ANTHROPIC_BASE_URL=https://api.rhumb.example \
  --env RHUMB_AMBIENT_DECOY= \
  --no-connect -y -- bash -c 'env > /tmp/probe.txt; sleep 120'
```

Result — all three decoy values gone from the agent's environment (0 occurrences
of each), replaced by exactly what was passed:

```
ANTHROPIC_API_KEY=scrubbed-by-rhumb
ANTHROPIC_BASE_URL=https://api.rhumb.example
RHUMB_AMBIENT_DECOY=
```

### Mandatory requirement for Task 4

Passing only the selected provider's credentials is **not sufficient** — any
`PROVIDER_CREDENTIAL_VARS` entry left unmentioned is inherited from the tmux
server. `argvCreate` must therefore emit an explicit `--env` for **every**
variable in `PROVIDER_CREDENTIAL_VARS` (`src/provider.ts`): the selected
provider's values as given, and every other entry blanked with `--env VAR=`.
That reproduces `sanitizedEnv`'s guarantee across the mngr boundary.

Setting a clean env on the `mngr` child process alone does **not** achieve this,
because a pre-existing tmux server bypasses it entirely.

## Q3 — incremental streaming or poll-only? Both, via different commands

- `mngr transcript TARGET --format human|json|jsonl [--tail N] [--head N]` is a
  **snapshot**. It has no follow flag.
- `mngr event TARGET [--follow] [--tail N]` **streams continuously**, polling for
  new events.

So `send()` can stream: use `mngr event --follow` for live turn events and
`mngr transcript --format jsonl` for `transcript()`.

**Better than the plan assumed:** mngr provides its own agent-agnostic transcript
abstraction, so Rhumb does not need to parse Claude's raw JSONL or know where it
lives. `transcript()` should shell out to `mngr transcript --format jsonl` rather
than reading `~/.claude/projects/…`. Event shape:

```json
{"timestamp":"…","type":"user_message","role":"user","content":"…","message_uuid":"…"}
{"timestamp":"…","type":"assistant_message","role":"assistant","text":"…",
 "tool_calls":[],"parts":[…],"finish_reason":"stop_sequence","usage":{…}}
```

## Verified command surface

| Purpose | Invocation |
| --- | --- |
| create | `mngr create <NAME> claude --no-connect -y [--env K=V …]` |
| list (ids) | `mngr list --ids` → one id per line |
| list (structured) | `mngr list --format json` → `{"agents":[{"id","name","type","state",…}]}` |
| message | `mngr message <NAME> -m "<TEXT>"` |
| transcript | `mngr transcript <NAME> --format jsonl` |
| stream | `mngr event <NAME> --follow` |
| stop | `mngr stop <NAME>` |
| destroy | `mngr destroy <NAME> --force -b` |

`mngr list` emits a noisy Docker-provider warning when Docker is not running;
`mngr config set --scope user providers.docker.is_enabled false` silences it.
Stdout is therefore not safe to parse without `--format json`.

## Agent identity — source review confirmed

The on-disk record at `~/.mngr/agents/<id>/data.json`:

```json
{
  "id": "agent-067b3d4227a54f92866dfd6211b994da",
  "name": "probe2",
  "type": "claude",
  "work_dir": "/Users/anderson/.mngr/worktrees/probe2-ebc18aba…",
  "create_time": "2026-08-03T20:05:58.557203+00:00",
  "labels": {"project": "mngr-probe"},
  "created_branch_name": "mngr/probe2"
}
```

The id is `agent-` + 32 hex characters — the random UUID4 the source review
predicted. The agent also sees `MNGR_AGENT_ID`, `MNGR_AGENT_NAME`,
`MNGR_AGENT_STATE_DIR`, `MNGR_HOST_DIR`, and `MNGR_AGENT_WORK_DIR` in its
environment.

This is a plaintext identifier in a plaintext file, with no attestation —
confirming the design's core premise: **the mngr agent id is an identifier, never
a credential.** The durable principal stays Rhumb-owned.

Also observed: mngr creates a **git worktree and branch** per agent
(`mngr/<name>`, work dir under `~/.mngr/worktrees/`). Slice 1 targets an existing
workspace, so branch and worktree lifecycle needs attention before slice 5.

## Impact on the plan

1. **Task 4 `argvCreate` must scrub the full `PROVIDER_CREDENTIAL_VARS` list**
   via explicit `--env`, not just pass the selected provider's credentials.
   This is a security requirement, not an optimization.
2. **Task 4 `send()` must not equate non-zero exit with non-delivery** —
   reconcile against the transcript first.
3. **Task 4 `transcript()` should call `mngr transcript --format jsonl`**
   instead of reading Claude's raw JSONL. `readTranscript` becomes a mngr call.
4. **`mngr list --format json` returns `{"agents":[…]}`**, not a bare array —
   the `liveIds()` parser must read the `agents` key.
5. **Task 5's prerequisite check should also assert bash 4+**, since a bash 3.2
   host fails at runtime in a way that looks like a hang.
6. Verified invocations replace the provisional ones in the plan's mechanics
   table.
